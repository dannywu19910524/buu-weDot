# buu-weDot v0.2.0 发布说明

项目与 GitHub 仓库名为 `buu-weDot`，npm 包标识为小写 `buu-wedot`，简介为“微信连接 dot”。2026-10-08 的命名调整只涉及品牌与包名称，状态 schema 仍为2；协议工具、事件与历史状态标识保持兼容。

面向已有 dot 的单用户微信桥接：通过 MCP Events 唤醒目标宿主，由原 dot 独立读取消息并提交一次 final。运行要求 Node 24.21 或更高的 Node 24 与 POSIX；无 npm 依赖，默认使用合成 mock。

## 提供的能力

- 持久化去重、固定 owner/绑定、签名事件、有限订阅与回调地址校验。
- 文本及 PNG/JPEG 入站、原生图片读取、共享一次 final 的文本或图片回复。
- 引用、本人文本缓存、合并读取、processing/typing、ACK、主动通知及显式本地二维码绑定；各项额外功能按自身开关及授权启用。
- 部署、停机备份、同 schema 回滚、排障和可重复本地验证文档。

发布准备修复了 FIFO 文件读取阻塞，以及 JSON Content-Type 前缀误放行/合法大小写误拒绝问题。许可证为 MIT，版权署名 buu；所有者已确认包括历史贡献在内的源码分发权。

本次准备还将 CLI 的 ready 输出移到退出信号处理器注册之后，避免收到 ready 后立即停止时遗漏优雅关闭；端口占用回归直接使用持续监听的临时端口，不再先释放再抢占。该修复针对代码可见时序窗口，不认定为首次通用验证失败的已确认根因。

## 验证范围

随包定义 126 项自动化测试：原 90 项、新安全回归 8 项、新扫描自测 28 项。最终结果以源码与安全解包 ZIP 的实际验证报告为准。历史 147 项与此不是同一清单，见 [历史审查追溯](LEGACY_REVIEW_TRACE.md)。两项 demo 使用进程内替代 provider，不连接真实微信。

本版本没有完成真实云端 MCP Events、目标 dot 或微信端到端验收；本地通过不证明这些链路已经可用。图片字节导出取决于目标宿主的实际授权通路。群聊、多账户、语音、视频和任意历史访问不属于本版本范围。
