# 排障：沿着链路核对，不把局部成功当成接通

先确定正在测试哪一层：本地合成、目标 dot 的 mock 订阅，或真实微信。请保留 mode、绑定类型、错误类别和是否通过各阶段的摘要。不要公开 Authorization、签名 secret、完整 callback URL、账号绑定文件、正文或数据库。

## 工具可以调用，事件目录却没有出现

工具和事件是不同能力。检查目标宿主是否支持该协议版本的 MCP Events、当前账户是否允许私有插件及事件任务，以及插件是否已刷新发现。应能观察到 `server/discover` 和 `events/list` 的成功结果；不能通过重复调用工具来补出宿主没有的事件功能。

普通桌面本地 MCP、stdio 客户端或某个工具能返回状态，均不足以证明当前 dot 支持原生事件唤醒。本项目只提供 HTTP MCP 服务端，不给不支持 Events 的客户端增加调度能力。

## 本地 demo 通过，目标 dot 没有醒来

本地 demo 使用受控的本地传输与合成消息，不接入真实宿主。公网试验还要分别验证：私有插件连接、目标会话创建的订阅、challenge、签名投递、宿主任务运行、该 dot 的读取和模拟 final。

callback 返回 `2xx` 后，宿主仍可能在后续才处理事件。没有对应任务记录时，结论应停留在“webhook 已获接收确认”，不能写成“dot 已收到”或“平台队列耗时已定位”。[官方接收语义](https://developers.openai.com/plugins/build/mcp-events#handle-delivery-responses)

## 身份失败：`not_authorized`

本机开发检查是否使用了生成配置对应的 local token 文件，以及 mode 是否仍为 mock。不要把这个 token 配到公网插件。

JWT 部署检查固定 issuer、resource/audience、subject、scope、签名公钥及有效期是否匹配。当前验证器接受预置 RSA 公钥的 RS256 短期令牌，不会从调用方提供的 URL 下载密钥，也不会自动相信代理传入的用户 ID。外部 OAuth 服务必须实际能够向此资源签发兼容令牌；不能假定任意 ChatGPT token 都满足条件。

配置文件与公钥文件不是热更新的权限控制台。修改文件后按部署流程停机、核验和重启；紧急阻断应先停止服务和撤销入口。不要通过放宽 owner、有效期或跳过验证解决认证问题。

## 订阅失败

| 错误或现象 | 检查与处理 |
| --- | --- |
| `callback_host_not_allowed` | 核对宿主实际提供的 callback 主机名与配置白名单。只在确认所属服务后加入精确主机名，不加通配符，不把错误详情自动写回配置。 |
| `unsafe_callback` / 地址被拒绝 | callback 必须符合 HTTPS 和地址策略；私网、环回、保留地址及重定向不适合作为公网投递目的地。 |
| `challenge_failed` / `callback_endpoint_error` | 检查接收器是否验证签名并返回本次 challenge；网络超时、非成功状态、错误 echo 均不能当作验证通过。 |
| `binding_already_subscribed` | 当前绑定已有另一个有效目的地。先通过原会话取消旧订阅，核验停止后再创建新订阅；不要直接覆盖别人的 callback。 |
| `replay_not_supported` | 本版没有事件历史 replay；不能通过任意 cursor 要求补发历史。 |
| 过一段时间不再投递 | 检查订阅是否到期，以及宿主是否在 `refreshBefore` 前续订。服务重启不等于自动永久续期。 |

订阅最长一小时，`ttlMs:null` 在本版仍得到有限期限。回调签名密钥来自订阅请求，不是微信 bot token。不要把两者混用。

## 有事件，但读不到消息

首先使用事件中的精确 `binding_id` 和 `message_id`。mock 注入时提交的 seed 不是最终消息 ID；应使用注入返回值或事件里的权威 ID。不要自己拼接 hash，也不要根据时间相近猜测事件归属。

若唤醒没有携带可用 ID，可以用 `read_pending_weixin` 一次独立核验最多三条待办；它不保证找到更老的待办，也不反推缺失唤醒的身份。需要继续定位时，用 `list_pending_weixin` 查有界列表，再对选定条目逐条 `get_message`。列表有 `has_more` 时按 `next_cursor` 翻页；读到同一批却没有进展时应停止重复调用并检查 final 状态。

`message_not_available` 可能意味着未获投递接收确认、超出一小时、绑定不符或原始记录不再可用。窗口以原始消息时间为基准。重发事件、重启进程或改调用 ID 都不应该延长它。

## 真实模式没有入站

先确认这是明确启用的 real 配置，绑定属于本人、接收与持久化已获同意，账号接口地址是本版支持的官方目标。绑定格式验证只做离线检查，不证明凭据目前有效。

本版严格接受本人、非群聊、已完成、受支持的单个 item。图片接收还受媒体开关和 PNG/JPEG 解析约束；语音、视频、文件、群聊、混合 item、超长、过旧或收发方不匹配不能自动转成支持。不要把这些情况报告为“微信完全不支持”或自动扩大授权范围。

服务端会保存轮询 cursor。不要清空 cursor 或去重账本来追赶历史；这可能改变重复消息处理。提供方会话暂停时按错误状态处理，本版对会话失效信号采用一小时暂停策略；不要循环尝试扫码或发送。

## 图片事件到了，却看不到图片

事件是定位通知，不直接携带可显示的图片像素。先以正确绑定读取原消息，再检查工具结果的原生 image 内容块。只展示 `structuredContent` 或只提取首段 text 的宿主处理方式会丢掉图片，即使服务端读取已经成功。

检查图片接收开关、固定 CDN 策略、PNG/JPEG 类型、解密参数、体积和像素限制。图片下载失败时应保留受控的 unavailable 状态；不要把内部下载 URL 或 AES key 交给模型让它自行抓取。

下载完成之前，owner、绑定或消息时限可能发生变化。末次复核失败时拒绝输出是预期行为。合并读取还要复核整批，并按每条消息的 `native_image_content_indexes` 对应原生内容块；不能将第一张图自动配给第一条文本。

## 图片发送失败

图片出站是独立新增的上传加发送链路，不由图片接收成功推导。输入必须是支持格式的受限图片字节；任意 URL、本机文件路径或未经核验的 MIME 声明都不是有效替代。

本版图片 final 不接受 `caption`；出现该参数会在 claim 前拒绝。需要文字说明时应选择文字 final，不能先用文字 final 再对同一消息发图片 final。

若 dot 只有一张可见预览或素材 ID，需要先确认宿主能否通过已有授权导出原字节。桥不内置附件、Library 或图片生成结果的导出适配器；不要将这类缺口误报为 provider 图片接口失败，也不要让模型编造 base64。

final 槽位在外部上传前占用。上传成功但消息发送失败、超时或中止，都可能留下无法确认的结果；不得清空状态再上传发送。mock 的图片 final 只验证协议与槽位，不证明微信已接收图片。

## 引用正文没有解析出来

区分 inline 文本、仅参考 ID、媒体元数据、未捕获和不可用。引用标记为 untrusted 是正常状态，不应由宿主升级成身份或控制指令。

仅参考 ID 的解析需要独立开启本人文本缓存；它只查同一绑定、原始一小时范围内已保留的文本。无同意、到期、容量淘汰、同 ID 冲突或旧数据未捕获，都可以导致未解析。不要改成跨会话搜索，也不要自动访问引用中的媒体地址。

## processing 成功，但没有“正在输入”

processing 是有限期本地状态；typing 是另一个可选的提供方提示。先核验两个开关及发送同意，再检查 lease 是否仍有效、消息是否已经 final、是否处于 waiting，以及提示请求是否被取消。

默认关闭的 `receiptTyping` 另控制最多一次五秒入站短提示，需同时启用 typing 和 processing。它不是工作 lease，不会因反复读取或重启而重播；开启后也不能据此认定 dot 已经开始处理。

即使接口返回受理，也不能证明模型正在执行或微信 UI 确实显示了提示。不要通过无限续期或反复调用来制造可见效果；只有确实处理这条消息时才更新 running。

## 主动通知被阻止

通知需要额外启用和同意，不能从任意入站文本推断。检查通知是否为绑定和授权之后的新事件、ID 是否稳定、事件是否仍在新鲜度窗口、是否有当前绑定的可用 context，以及限频或未解决结果是否阻断了发送。

context 年龄上限是本地策略，提供方有效期未知。到期或被提供方拒绝时，不应修改创建时间伪造新鲜 context。相同通知 ID 不同内容是冲突；blocked 或 uncertain 也不能通过换一个 ID 自动重试。

## final 没有表现成一条微信消息

| 返回或状态 | 含义 |
| --- | --- |
| `simulated:true, sent:false` | mock final 已记录，未向微信发送。 |
| `send_not_authorized` | real 绑定没有显式发送同意；只读测试不会自动开启发送。 |
| `reply_already_claimed` | 该消息已占 final；不要换 ID 重试。 |
| 相同回复返回 `duplicate:true` | 复用了已有成功结果，没有再次发送。 |
| `send_result_uncertain` / `sent:null` | 已进入一次发送尝试但无法确认结果；保持状态并人工核对，不自动重试。 |
| real `sent:true` | 满足本项目对提供方响应的确认条件；不等于对方已阅读。 |

文字和图片 final 都用于语义完成的最终回复，并共享该消息的 final 约束。用 final 发“收到，稍等”会消耗这个槽位。可选 processing / typing 和临时文字确认是独立功能，需要按实际开关和协议使用；不能拿主动通知绕过已经不确定的 final。

出现 `uncertain` 时，服务重启会继续保持占用保护。不要回退数据库快照、手工把状态改成 ready、改 client ID 或复制消息到新 ID。若业务需要补充沟通，应由本人核对后另行决策，而不是隐式重试原发送。

工具等待期间令牌可能到期。返回前的身份检查能够拒绝暴露结果，但不能撤回已经发出的微信请求。因此，final 返回认证错误或连接中断，也不能据此推断“尚未发送”；重新取得合法身份后先核对原消息状态，不能直接重发。

## 存储或启动失败

`private_storage_required` 通常涉及目录权限、文件所有者、符号链接或非私有位置。`state_identity_or_schema_invalid` 表示数据库、密钥、mode、owner 或账号身份不匹配。应恢复同一部署的正确配置与密钥，不要为了启动而删库。

旧文字候选 0.1 与扩展版状态 schema 2 双向不兼容，运行时与发布切换都会拒绝。保持停机并核对代码/数据库版本；不能让原绑定换一个空数据库重试。现有运维脚本只切同 schema 扩展副本，不提供保留账本的跨 schema 迁移。

显式二维码命令要求真实 TTY、仓库外的全新私有目录和 `--run`；缺少这些条件会停止。验证码只在提供方要求后隐藏输入，取消或五分钟到期后需结束本次会话，不得让事件或服务器自动重启登录。QR CLI 的本地 stub 测试通过不代表真实二维码状态分支已验收。

正文过期后的清理与持久去重是不同策略。`dedupe_ledger_full` 需要容量处置方案；此候选没有在线压缩和跨版本数据迁移工具。任何会删除去重历史的操作都需要重新评估可能重复发送的范围。

## 延迟很大时怎样记录

记录以下阶段的存在性与时间来源：微信 source、桥接持久化、callback 发起/返回、宿主首次实际观察、授权读取返回、正文形成、final 发起/返回、提供方确认。只记录必要元数据，精确关联信息留在私有环境。

桥接内部耗时不能替代原生工具的完整等待，callback 时间不能替代 dot 的实际唤醒，final 工具返回也不总等于提供方 ACK。缺少关联、跨机器时钟未校准或只看到秒级界面时间时，标为未知。不要为了获得好看的指标，把正文就绪后的发送等待算进思考时间，或拿闭源环境的 mock 结果冒充公开版实测。
