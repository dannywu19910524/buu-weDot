## 可重复的本地检查

使用 `.node-version` 对应的 Node 24.21.0，或符合 `>=24.21.0 <25` 的已审查 Node 24 运行时。在干净解包的源码根目录执行：

```sh
node --version
npm run --silent verify:release > ../candidate-verification.json
```

报告必须在源码树外，先检查命令退出码为零，再确认它是可解析的 JSON 且 `passed:true`。这里的 `--silent` 用来去掉 npm 生命周期提示，否则重定向文件会包含非 JSON 的提示行。也可直接运行 `node scripts/verify-release.mjs > ../candidate-verification.json`。报告失败时可分别执行 `npm test`、`npm run demo:mock`、`npm run demo:features` 和 `node scripts/scan-public.mjs .` 定位问题。不要将失败报告、跳过的测试或不支持版本下的执行写成通过。

验证入口检查运行时、候选许可状态与无 npm 依赖元数据、当前静态导入边界，随后执行所有 `tests/*.test.mjs`、两项 mock demo 和公开树扫描，并比较验证前后的文件树摘要。它输出每个文件的路径、大小和 SHA-256；规范摘要采用按路径排序、对象键顺序为 `path`、`sha256`、`size`、无多余空白的 JSON 数组编码。静态导入检查不是通用 JavaScript 解析器或供应链认证；内容扫描也不能证明所有敏感资料都已排除。

测试使用生成的合成媒体、一次性本地测试密钥、替代 provider/回调及本机回环监听。没有真实 OAuth、微信凭据、消息或扫码；运行环境需允许本机回环监听以及 POSIX 的 `mkfifo`。目录中的 8 项 `release-security` 反例及 28 项扫描器自测随包提供。项目原有 90 项加上这 36 项，当前定义为 126 项；不要叠加历史回执的独立 29/28 项或重复运行数。以实际报告的计数和结果为准。

最终归档只包含经扫描的源码树；不要包含验证报告、私有 denylist、运行时、测试临时目录、配置或数据库。安全解压最终 ZIP 到另一空目录，核对成员均为该根目录内的普通文件、无链接/重复路径/加密成员，重新运行同一入口，并将文件清单与受测树逐项比对。ZIP 摘要在包外保存，避免包含自身摘要的递归问题。
